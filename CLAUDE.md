## Operating rules
- Check the current branch and git status first. Never overwrite uncommitted teammate work.
- Get a named owner, GitHub issue, file scope, and acceptance criteria before coding.
- If the challenge has not officially begun, do not develop challenge-specific code.
- Stay within your assigned branch and files; flag shared-file conflicts before editing.
- Make small, reproducible, testable changes. Keep `main` demonstrable.
- Do not merge, force-push, change another person's branch, or delete others' work without explicit approval.
- Never fabricate experiments or benchmark numbers; record the data split, seed, metrics and evidence.
- Respect challenge rules on datasets, AI services and external resources. Never commit credentials or restricted data.
- When finishing: list changed files, tests run and actual results, known limitations, blockers, and recommended next action.
- Update project docs when relevant, but do not present local changes as synced until pushed and merged.

The shared written project context is authoritative; ChatGPT and Claude chat histories are not synchronized.
